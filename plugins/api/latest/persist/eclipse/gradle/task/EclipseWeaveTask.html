Package: persist.eclipse.gradle.task

[Groovy] Class EclipseWeaveTask

        • persist.eclipse.gradle.task.EclipseWeaveTask 
        • @DisableCachingByDefault(because: Weaving modifies classes in place)
abstract class EclipseWeaveTask
extends DefaultTask

          A custom Gradle task that handles compile-time static bytecode weaving for EclipseLink entities.

          This task intercepts standard compilation outputs and executes the official EclipseLink StaticWeave command-line processor in an isolated JVM process using ExecOperations. In-place bytecode manipulation updates entities to natively handle lazy loading hooks, fetch graph optimizations, and active dirty tracking, entirely removing the need for a dynamic runtime javaagent.

          Designed to satisfy strict Gradle Configuration Cache rules and incremental build validations, this task isolates its input/output directory tracking to avoid cache invalidation loops.

          Since:
          1.0.0

            • @TaskAction
              void weave()

              The core action block for the task execution.

              Creates a temporary staging sandbox directory, copies processed resources into it, then dynamically parses the persistence.xml to discover <jar-file> entries. Matching JAR files from the jarFileClasspath are resolved by name and copied into their expected relative paths within the sandbox, ensuring the EclipseLink StaticWeave processor can locate cross-module dependencies correctly.

              Finally, spawns an isolated Java process running the org.eclipse.persistence.tools.weaving.jpa.StaticWeave main class, using the sandbox as the -persistenceinfo source to map byte structures cleanly from the raw source to the enhanced output target.

              Since:
              1.5.1 Added staging sandbox with dynamic JAR resolution from persistence.xml
