[Groovy] Class EclipseStaticWeavePlugin

      Plugin<Project>
      class EclipseStaticWeavePlugin
extends Object
implements Plugin<Project>

      Main entry point for the EclipseLink Static Weaving Plugin.

      This plugin applies the JavaPlugin and registers a high-performance, incremental bytecode modification task for every discovered source set whose java.srcDirs contain at least one directory that physically exists on disk. It programmatically triggers EclipseLink's StaticWeave execution framework post-compilation, transforming standard JPA entities in-place within the compilation pipeline output boundaries. When the jpa configuration is present (e.g. via JakartaPersistencePlugin), the weave configuration lazily extends from it to inherit platform version constraints.

      This enables performance optimizations such as strict lazy loading, fetch graph mechanics, and advanced inline dirty tracking without requiring an active -javaagent JVM argument at runtime.

      Since 1.5.1: The weaving task is automatically skipped if no META-INF/persistence.xml is found in the processed resources output directory, preventing unnecessary failures in modules that do not define a persistence unit. Additionally, the plugin now resolves a source-set-specific jarFile configuration (e.g. jarFile for main, testJarFile for test) and feeds it to the jarFileClasspath, enabling correct resolution of <jar-file> entries in multi-module projects.

      Since 1.5.4: The default org.eclipse.persistence.jpa weave dependency is now added conditionally — only when the user has not declared any custom dependencies in the weave configuration. This allows projects to substitute or override the default weave dependency without conflicts.

      Since 1.7.0: The plugin now registers a source-set-specific internal weavingClasspath configuration (e.g. weavingClasspath for main, testWeavingClasspath for test) with canBeConsumed = false and canBeResolved = true. This configuration lazily extends from the global user-facing weave configuration, isolating the weaving task execution graph. The EclipseWeaveTask now reads its weaveClasspath directly from this isolated internal configuration provider, protecting task property resolution states and maintaining full compatibility with the Gradle Configuration Cache. The weaving task is only registered for source sets that have at least one physical Java source directory present on disk. Source sets with no existing java.srcDirs directories are silently skipped, preventing clean IDE workspaces from being cluttered with empty tasks (e.g. eclipseWeaveTestClasses).

        • @Override
          void apply(Project project)

          Applies the EclipseLink static weaving configuration to the target project.

          Creates the weave configuration, registers per-source-set EclipseWeaveTask instances with isolated classpath resolution, hooks the weave task into the build lifecycle, and provisions the default org.eclipse.persistence.jpa dependency when no user override is present.

          Parameters:
          project - The target Gradle project.
