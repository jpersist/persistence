[Groovy] Class JakartaPersistencePlugin

      Plugin<Project>
      class JakartaPersistencePlugin
extends Object
implements Plugin<Project>

      Gradle plugin that manages Jakarta Persistence (JPA) descriptor generation.

      Registered with plugin id io.github.jpersist.jpa, this plugin:

      1. Applies the JavaPlugin.
      2. Creates a jpa dependency configuration for propagating platform/BOM version constraints into Java compilation and annotation processing configurations (compileOnly or compileOnlyApi when JavaLibraryPlugin is applied, annotationProcessor).
      3. Registers a global, non-resolvable modelgenProcessor configuration container that centralizes modelgen annotation processor dependencies. Each source set's annotationProcessor configuration lazily extends from this unified root via extendsFrom, so that provider-specific plugins (e.g. Hibernate or EclipseLink) only need to target the single modelgenProcessor configuration.
      4. Registers the persistence NamedDomainObjectContainer of PersistenceExtension as the top-level DSL extension.
      5. For each Java source set (e.g. main, test) whose java.srcDirs or resources.srcDirs contain at least one directory that physically exists on disk:
        • Creates a jarFile (or <sourceSet>JarFile) dependency configuration for declaring module JARs to be injected as <jar-file> entries. The jarFile configuration extends implementation (or api when the java-library plugin is present).
        • Automatically initializes a PersistenceExtension instance in the container, keyed by the source set name.
        • Automatically parses any existing persistence.xml template in the source set's resources and pre-registers the <persistence-unit> names into the extension, so they can be configured from the build script without explicit re-declaration.
        • Registers a processPersistenceDescriptor (or process<SourceSet>PersistenceDescriptor) ProcessPersistenceDescriptor task that generates or merges the final persistence.xml.
        • Registers the generated resources directory into the source set so that IDEs such as Eclipse Buildship and IntelliJ can index the directory and resolve META-INF/persistence.xml instantly.
        • Wires the task output into the source set's processResources so the generated descriptor ends up in the JAR.
        • Registers a validatePersistenceSchema (or validate<SourceSet>PersistenceSchema) ValidatePersistenceSchema task that validates entity mappings against the database schema using an isolated worker process.
        • Registers a generateJPAGraalVMMetadata (or generate<SourceSet>JPAGraalVMMetadata) GenerateJPAGraalVMMetadata task that produces a GraalVM reflect-config.json for all discovered JPA entity classes.

      Individual persistence units can be skipped by setting their enabled property to false. The generated XML output can be customized via the outputProperties map or the transformer DSL block.

      Persistence units already declared in a user-provided persistence.xml template are automatically registered into the extension at configuration time, allowing build scripts to customise them (e.g. disable or override properties) without re-declaring them.

      When the configured JPA version is a legacy specification version (2.0, 2.1, or 2.2), the plugin automatically switches annotation scanning from the jakarta.persistence namespace to the javax.persistence namespace, ensuring correct entity discovery for projects that still target the older Java Persistence API.

      Since 1.7.0: Per-source-set task and configuration registration is conditional — the plugin inspects sourceSet.java.srcDirs and sourceSet.resources.srcDirs at configuration time and only creates tasks and dependency configurations when at least one physical directory exists on disk. This prevents clean IDE workspaces from being cluttered with empty tasks (e.g. lintTestNamedQueries) when a target source set contains no operational files.

      This plugin replaces the deprecated persistence-gradle-plugin (io.github.jpersist.persistence).

      Since:
      1.1.0

        • @Override
          void apply(Project project)

          Applies the Jakarta Persistence plugin configuration to the target project.

          Registers the jpa and modelgenProcessor configurations, the persistence extension container, and per-source-set task registrations for descriptor processing, GraalVM metadata generation, schema validation, and named query linting.

          Parameters:
          project - The target Gradle project.

        • static Provider<ConfigurableFileCollection> resolvePersistenceToolsFiles(Project project, Provider<String> jpaVersionProvider, ClassLoader classLoader)

        • static String resolvePersistenceToolsVersion()

          Resolves the version of the persistence-tools-api library that is currently on the plugin's own classpath.

          The version is extracted from the Implementation-Version attribute of the META-INF/MANIFEST.MF inside the JAR that contains the persist.api.spi.PersistenceServiceProvider SPI class. This allows downstream plugins (e.g. the Hibernate enhancement plugin) to declare matching provider dependencies at the exact same version without hard-coding version strings.

          throws:
          org.gradle.api.GradleException if the version lookup encounters an unexpected I/O or security error.
          Returns:
          The resolved version string, or null when the version cannot be determined (e.g. when running from exploded classes during development).
          Since:
          1.8.0
