jPersist — Jakarta Persistence Gradle Plugins

jPersist is a suite of Gradle plugins that simplify development with Jakarta Persistence API (JPA) frameworks. It automates key build-time tasks — descriptor generation & merging, schema validation, static metamodel generation, bytecode enhancement/weaving, GraalVM native image metadata generation, and static compile-time named query linting — for both EclipseLink and Hibernate.

Available Plugins

Jakarta Persistence

Plugin IDDescription
io.github.jpersist.jpa Manages Jakarta Persistence (JPA) descriptor generation and merging, schema validation, GraalVM native image metadata generation, and static compile-time named query linting. Creates the {@code jpa} dependency configuration for platform/BOM version alignment and registers the {@code persistence} extension DSL with {@code processPersistenceDescriptor}, {@code validatePersistenceSchema}, {@code generateJPAGraalVMMetadata}, and {@code lintNamedQueries} tasks. See {@link persist.jakarta.gradle.plugin.JakartaPersistencePlugin}.

What's New in v1.7.0

Version 1.7.0 introduces multi-tenant schema validation to the Jakarta Persistence plugin (io.github.jpersist.jpa):

  • Multi-Tenant Validation Matrix — The {@link persist.jakarta.gradle.task.ValidatePersistenceSchema validatePersistenceSchema} task now iterates over a named set of tenant database profiles, validating every active persistence unit against each tenant independently. Failures are collected across the entire matrix and reported in a single summary.
  • Tenant DSL Extension — The new {@link persist.jakarta.gradle.extension.TenantValidationExtension} class represents a single tenant profile with its own JDBC connection properties. Profiles are declared inside the {@code validation} block via a new {@code tenants} named container: 
    persistence {
    main {
        validation {
            tenants {
                primary {
                    url = 'jdbc:h2:mem:primary_db;DB_CLOSE_DELAY=-1'
                }
                secondary {
                    url = 'jdbc:h2:mem:secondary_db;DB_CLOSE_DELAY=-1'
                }
            }
        }
    }
}
    When no tenants are configured, the base validation properties are used as a single default profile for backward compatibility.
  • SPI-based Schema Validator — Schema validation is now delegated to an SPI-loaded {@link persist.lint.api.spi.SchemaValidator} obtained via {@link persist.lint.api.spi.SchemaValidatorFactory}, replacing the previous direct use of the JPA {@code Persistence} bootstrap API.
  • Entity Class Discovery — The task now receives a list of entity class names discovered by the ASM bytecode scanner, forwarding them to the SPI validator for precise mapping resolution.
  • ValidationExtension Refactoring — {@link persist.jakarta.gradle.extension.ValidationExtension} has been converted from an interface to an abstract class to support constructor injection and the managed {@code tenants} container.

What's New in v1.6.0

Version 1.6.0 introduces static compile-time named query linting to the Jakarta Persistence plugin (io.github.jpersist.jpa):

  • Lint Named Queries — A new {@link persist.jakarta.gradle.task.LintNamedQueries lintNamedQueries} task performs a static, compile-time AST verification pass over all {@code @NamedQuery} and {@code @NamedStoredProcedureQuery} definitions discovered in the compiled source set output. The task uses ASM bytecode scanning to locate query annotations, then validates JPQL/HQL syntax and parameter naming conventions using an ANTLR4-based parser loaded via SPI. Processing runs inside an isolated Gradle Worker classloader.
  • Linter DSL Extension — The new {@link persist.jakarta.gradle.extension.LinterExtension} interface provides configuration options ({@code enabled}, {@code failOnError}, {@code ignoreWarnings}) embedded inside {@link persist.jakarta.gradle.extension.PersistenceExtension}. It is accessible via the {@link persist.jakarta.gradle.extension.PersistenceExtension#linter(org.gradle.api.Action) linter(Action)} DSL method: 
    persistence {
    main {
        linter {
            enabled = true
            failOnError = true
            ignoreWarnings = false
        }
    }
}

What's New in v1.5.0

Version 1.5.0 introduces three major features to the Jakarta Persistence plugin (io.github.jpersist.jpa):

  • JPA Schema Validation — A new {@link persist.jakarta.gradle.task.ValidatePersistenceSchema validatePersistenceSchema} task boots an isolated JVM worker process to validate that JPA entity mappings match the database schema. The task uses Gradle's {@link org.gradle.workers.WorkerExecutor} with classloader isolation to avoid classpath conflicts with the Gradle daemon. Database connection properties are configurable via the new {@link persist.jakarta.gradle.extension.ValidationExtension validation} DSL block inside each source set's {@code persistence} extension: 
    persistence {
    main {
        validation {
            url = 'jdbc:h2:mem:my_validation_db;DB_CLOSE_DELAY=-1'
            driver = 'org.h2.Driver'
            user = 'sa'
            password = ''
        }
    }
}
    When no properties are configured, the task defaults to an in-memory H2 database. See {@link persist.jakarta.gradle.worker.SchemaValidationWorker} for implementation details.
  • GraalVM Native Image Support — A new {@link persist.jakarta.gradle.task.GenerateJPAGraalVMMetadata generateJPAGraalVMMetadata} task produces a {@code reflect-config.json} file containing all discovered JPA entity classes, enabling ahead-of-time (AOT) reflection registration for GraalVM native image compilation.
  • Validation DSL Extension — The {@link persist.jakarta.gradle.extension.ValidationExtension} class provides optional JDBC connection properties ({@code url}, {@code driver}, {@code user}, {@code password}) and an optional multi-tenant {@code tenants} container embedded inside {@link persist.jakarta.gradle.extension.PersistenceExtension}. It is accessible via the {@link persist.jakarta.gradle.extension.PersistenceExtension#validation(org.gradle.api.Action) validation(Action)} DSL method.

Quick Start

plugins {
    id 'io.github.jpersist.hibernate-persistence'  // or 'io.github.jpersist.eclipse-persistence'
}

dependencies {
    jpa platform('org.hibernate.orm:hibernate-platform:6.6.5.Final')
}

Key Design Principles

  • No hardcoded dependency versions — The plugins add JPA engine dependencies without version strings. Use the jpa configuration with a platform BOM to centrally manage versions.
  • Configuration Cache compliant — All plugins and tasks are fully compatible with Gradle's Configuration Cache for maximum build performance.
  • Incremental build support — Tasks use proper input/output tracking and produce UP-TO-DATE or NO-SOURCE outcomes when appropriate.
  • Per-source-set configuration — Plugins automatically configure tasks for every source set (main, test, custom variants).
  • Eclipse IDE integration — Plugins hook into Eclipse Buildship to register generated source directories in the IDE classpath.

Package Organization

  • {@link persist.jakarta.gradle.plugin} — Jakarta Persistence plugin for JPA descriptor generation and version management.
  • {@link persist.jakarta.gradle.extension} — Jakarta Persistence DSL extension configuration model, including XML formatting options.
  • {@link persist.jakarta.gradle.task} — Jakarta Persistence build-time task implementations, including schema validation, GraalVM metadata generation, and named query linting.
  • {@link persist.jakarta.gradle.worker} — Gradle Worker API implementations for isolated JPA schema validation and named query analysis.
  • {@link persist.platform.gradle.plugin} — (Deprecated) Platform alignment plugin for centralized version management.
  • {@link persist.eclipse.gradle.plugin} — EclipseLink plugin implementations.
  • {@link persist.eclipse.gradle.extension} — EclipseLink DSL extension configuration model.
  • {@link persist.eclipse.gradle.task} — EclipseLink build-time task implementations.
  • {@link persist.hibernate.gradle.plugin} — Hibernate plugin implementations.
  • {@link persist.hibernate.gradle.extension} — Hibernate DSL extension configuration model.
  • {@link persist.hibernate.gradle.task} — Hibernate build-time task implementations.
