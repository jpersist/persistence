Persistence Tools Libraries

The Persistence Tools Libraries (group {@code io.github.jpersist.tools}) provide build-time validation and bytecode enhancement of JPA persistence artifacts — named JPQL queries, stored procedure declarations, database schemas, and entity classes — without deploying the application. By compiling query strings against the entity metamodel, comparing the metamodel with a live database schema, and enhancing entity bytecode at build time, syntax errors, unknown entity references, invalid property paths, schema mismatches, and missing runtime instrumentation are caught early.

Architecture

The library is organised into two complementary SPI hierarchies:

Persistence Linting

Rooted in {@link persist.lint.api.spi.PersistenceLinter} (the marker interface for all linting operations) and {@link persist.lint.api.spi.PersistenceLinterFactory} (the base factory with {@link java.util.ServiceLoader}-based discovery):

  • {@link persist.lint.api.spi.NamedObjectParser} / {@link persist.lint.api.spi.NamedObjectParserFactory} — parses and validates named JPQL queries and stored procedure declarations, returning {@link persist.lint.api.NamedObjectDescriptor} results with parameter metadata.
  • {@link persist.lint.api.spi.SchemaValidator} / {@link persist.lint.api.spi.SchemaValidatorFactory} — validates the entity metamodel against a live database schema via JDBC.

Hibernate Bytecode Enhancement

Rooted in {@link persist.hibernate.enhance.spi.HibernateEnhancer} (the bytecode transformation contract) and {@link persist.hibernate.enhance.spi.HibernateEnhancerProvider} (the {@link java.util.ServiceLoader}-based provider):

  • {@link persist.hibernate.enhance.spi.HibernateEnhancer} — transforms compiled entity class bytes to add Hibernate-specific instrumentation such as lazy-loading proxies, inline dirty tracking, bi-directional association management, and extended enhancement.
  • {@link persist.hibernate.enhance.spi.HibernateEnhancerProvider} — discovers and creates namespace-specific enhancer instances for a given JPA specification version.

Both hierarchies share a common root through {@link persist.api.spi.PersistenceServiceProvider}, which maps a JPA specification version string (e.g. {@code "3.1"} or {@code "2.2"}) to a persistence namespace ({@code "jakarta"} for JPA 3.x, {@code "javax"} for JPA 2.x) and locates the matching provider via the {@link java.util.ServiceLoader} mechanism. Provider implementations for each JPA namespace are shipped in separate modules.

What's New

Version 3.0.0

Version 3.0.0 relocates all published artifacts to the {@code io.github.jpersist.tools} group and introduces the following changes:

  • Group relocation — all Maven coordinates now use the {@code io.github.jpersist.tools} group identifier.
  • {@link persist.api.spi.PersistenceServiceProvider} — new root service-provider interface shared by both the linting and enhancement hierarchies, with version-to-namespace mapping and generic {@link java.util.ServiceLoader} discovery via {@link persist.api.spi.PersistenceServiceProvider#getServiceProvider(String, Class)}.
  • {@link persist.hibernate.enhance.spi.HibernateEnhancer} and {@link persist.hibernate.enhance.spi.HibernateEnhancerProvider} — new SPI for build-time Hibernate bytecode enhancement of entity classes, with configurable options for lazy initialisation, dirty tracking, association management, and extended enhancement.

Version 2.1.0

Version 2.1.0 introduced the unified linter hierarchy:

  • {@link persist.lint.api.spi.PersistenceLinter} — marker interface that serves as the root type for all linting operations.
  • {@link persist.lint.api.spi.PersistenceLinterFactory} — base factory with generic discovery via {@link persist.lint.api.spi.PersistenceLinterFactory#newPersistenceLinterFactory(String, Class)}.
  • {@link persist.lint.api.spi.SchemaValidator} and {@link persist.lint.api.spi.SchemaValidatorFactory} — SPI for build-time database schema validation against the entity metamodel.

Version 2.0.0

Version 2.0.0 introduced the {@link persist.lint.api.spi.NamedObjectParser} and {@link persist.lint.api.spi.NamedObjectParserFactory} APIs with support for validating {@link persist.lint.api.NamedObjectType#STORED_PROCEDURE named stored procedures} alongside named queries, returning rich {@link persist.lint.api.NamedObjectDescriptor} results containing parameter metadata.

Modules

persistence-tools-api
Defines the Service Provider Interfaces (SPIs): {@link persist.api.spi.PersistenceServiceProvider}, {@link persist.lint.api.spi.PersistenceLinter}, {@link persist.lint.api.spi.PersistenceLinterFactory}, {@link persist.lint.api.spi.NamedObjectParser}, {@link persist.lint.api.spi.NamedObjectParserFactory}, {@link persist.lint.api.spi.SchemaValidator}, {@link persist.lint.api.spi.SchemaValidatorFactory}, {@link persist.hibernate.enhance.spi.HibernateEnhancer}, and {@link persist.hibernate.enhance.spi.HibernateEnhancerProvider}. This module contains no implementation; provider modules are discovered at runtime through the {@link java.util.ServiceLoader} mechanism. It also hosts the shared model types {@link persist.lint.api.NamedObjectDescriptor} and {@link persist.lint.api.NamedObjectType}, as well as the enhancement option enum {@link persist.hibernate.enhance.spi.HibernateEnhancer.Option}.
persistence-tools-jakarta
Jakarta Persistence (JPA 3.x) provider. Uses Hibernate ORM 6 to compile JPQL queries into Semantic Query Model (SQM) trees, validate database schemas, and enhance entity bytecode.
Key classes: {@link persist.lint.jakarta.JakartaNamedObjectParserFactory}, {@link persist.lint.jakarta.JakartaNamedObjectParser}, {@link persist.lint.jakarta.JakartaSchemaValidatorFactory}, {@link persist.lint.jakarta.JakartaSchemaValidator}, {@link persist.hibernate.enhance.jakarta.JakartaHibernateEnhancerProvider}, and {@link persist.hibernate.enhance.jakarta.JakartaHibernateEnhancer}.
persistence-tools-legacy
Legacy {@code javax.persistence} (JPA 2.x) provider. Uses Hibernate 5 and its AST-based query translator to validate JPQL queries and database schemas, and to enhance entity bytecode.
Key classes: {@link persist.lint.legacy.LegacyNamedObjectParserFactory}, {@link persist.lint.legacy.LegacyNamedObjectParser}, {@link persist.lint.legacy.LegacySchemaValidatorFactory}, {@link persist.lint.legacy.LegacySchemaValidator}, {@link persist.hibernate.enhance.legacy.LegacyHibernateEnhancerProvider}, and {@link persist.hibernate.enhance.legacy.LegacyHibernateEnhancer}.
persistence-tools-bom
Bill of Materials (BOM) for convenient dependency management of all Persistence Tools modules.

Getting Started

Enhancing Entity Bytecode

Use {@link persist.hibernate.enhance.spi.HibernateEnhancerProvider#getHibernateEnhancerProvider(String)} to obtain the appropriate provider for a given JPA specification version, then create a {@link persist.hibernate.enhance.spi.HibernateEnhancer} to transform entity classes at build time: 

{@code
    HibernateEnhancerProvider provider =
        HibernateEnhancerProvider.getHibernateEnhancerProvider("3.1");

    HibernateEnhancer enhancer = provider.getEnhancer(
        classesDir,
        classpathFiles,
        Map.of(
            HibernateEnhancer.Option.LAZY_INITIALIZATION, true,
            HibernateEnhancer.Option.DIRTY_TRACKING, true));

    byte[] enhancedBytes = enhancer.enhance(
        "com.example.Order", originalClassBytes);
}

Validating Named Queries and Stored Procedures

Use {@link persist.lint.api.spi.NamedObjectParserFactory#newNamedObjectParserFactory(String)} to obtain the appropriate factory for a given JPA specification version, then create a {@link persist.lint.api.spi.NamedObjectParser} to validate named queries and stored procedures: 

{@code
    NamedObjectParserFactory factory =
        NamedObjectParserFactory.newNamedObjectParserFactory("3.1");

    try (NamedObjectParser parser = factory.newNamedObjectParser(entityClassNames)) {

        // Validate a named query
        NamedObjectDescriptor queryDescriptor = parser.parseQuery(
            "Order.findByStatus",
            "SELECT o FROM Order o WHERE o.status = :status");

        // Validate a named stored procedure
        NamedObjectDescriptor procDescriptor = parser.parseStoredProcedure(
            "Order.archiveOldOrders",
            "sp_archive_orders",
            Set.of("cutoffDate", "archiveTable"));
    }
}

Validating Database Schemas

Use {@link persist.lint.api.spi.SchemaValidatorFactory#newSchemaValidatorFactory(String)} to obtain a schema validator factory, then create a {@link persist.lint.api.spi.SchemaValidator} and validate the entity metamodel against a live database: 

{@code
    SchemaValidatorFactory factory =
        SchemaValidatorFactory.newSchemaValidatorFactory("3.1");
    SchemaValidator validator = factory.newSchemaValidator(entityClassNames);

    validator.validateSchema(Map.of(
        "driver",   "org.h2.Driver",
        "url",      "jdbc:h2:mem:testdb",
        "username", "sa",
        "password", ""));
}

Generic Factory Discovery

The {@link persist.lint.api.spi.PersistenceLinterFactory#newPersistenceLinterFactory(String, Class)} method provides a generic way to discover any linter factory subtype for a given JPA version: 

{@code
    // Equivalent to NamedObjectParserFactory.newNamedObjectParserFactory("3.1")
    NamedObjectParserFactory parserFactory =
        PersistenceLinterFactory.newPersistenceLinterFactory(
            "3.1", NamedObjectParserFactory.class);

    // Equivalent to SchemaValidatorFactory.newSchemaValidatorFactory("3.1")
    SchemaValidatorFactory schemaFactory =
        PersistenceLinterFactory.newPersistenceLinterFactory(
            "3.1", SchemaValidatorFactory.class);
}
