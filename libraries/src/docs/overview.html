Persistence Tools Libraries

The Persistence Tools Libraries (group {@code io.github.jpersist.tools}) provide build-time validation and bytecode enhancement of JPA persistence artifacts — named JPQL queries, stored procedure declarations, database schemas, and entity classes — without deploying the application. By compiling query strings against the entity metamodel, comparing the metamodel with a live database schema, and enhancing entity bytecode at build time, syntax errors, unknown entity references, invalid property paths, schema mismatches, and missing runtime instrumentation are caught early.

Architecture

The library is organised into two complementary SPI hierarchies:

Persistence Linting

Rooted in {@link persistence.tools.PersistenceLinter} (the marker interface for all linting operations) and {@link persistence.tools.spi.PersistenceLinterFactory} (the base factory with {@link java.util.ServiceLoader}-based discovery):

  • {@link persistence.tools.NamedObjectParser} / {@link persistence.tools.spi.NamedObjectParserFactory} — parses and validates named JPQL queries and stored procedure declarations, returning {@link persistence.tools.NamedObjectDescriptor} results with parameter metadata.
  • {@link persistence.tools.SchemaValidator} / {@link persistence.tools.spi.SchemaValidatorFactory} — validates the entity metamodel against a live database schema via JDBC.

Hibernate Bytecode Enhancement

Rooted in {@link persistence.tools.Enhancer} (the bytecode transformation contract) and {@link persistence.tools.spi.EnhancerProvider} (the {@link java.util.ServiceLoader}-based provider):

  • {@link persistence.tools.Enhancer} — transforms compiled entity class bytes to add Hibernate-specific instrumentation such as lazy-loading proxies, inline dirty tracking, bi-directional association management, and extended enhancement.
  • {@link persistence.tools.spi.EnhancerProvider} — discovers and creates namespace-specific enhancer instances for a given JPA specification version.

Both hierarchies share a common root through {@link persistence.tools.spi.PersistenceServiceProvider}, which maps a JPA specification version string (e.g. {@code "3.1"} or {@code "2.2"}) to a persistence namespace ({@code "jakarta"} for JPA 3.x, {@code "javax"} for JPA 2.x) and locates the matching provider via the {@link java.util.ServiceLoader} mechanism. Provider implementations for each JPA namespace are shipped in separate modules.

What's New

Version 3.1.0

Version 3.1.0 introduces native support for the Java Platform Module System (JPMS). All library modules now ship with explicit {@code module-info.java} descriptors, enabling strong encapsulation and reliable compile-time dependency resolution on the module path.

  • Module descriptors — each library artifact declares an explicit JPMS module: {@code io.github.jpersist.tools.api} (core SPIs and model types), {@code io.github.jpersist.tools.jakarta} (Jakarta Persistence / Hibernate 6 provider), and {@code io.github.jpersist.tools.legacy} (legacy {@code javax.persistence} / Hibernate 5 provider).
  • Service declarations — the API module declares {@code uses} directives for all SPI interfaces ({@link persistence.tools.spi.PersistenceServiceProvider}, {@link persistence.tools.spi.PersistenceLinterFactory}, {@link persistence.tools.spi.NamedObjectParserFactory}, {@link persistence.tools.spi.SchemaValidatorFactory}, and {@link persistence.tools.spi.EnhancerProvider}), while the provider modules register their implementations via {@code provides…with} directives, allowing {@link java.util.ServiceLoader} discovery on the module path.
  • Strong encapsulation — provider modules ({@code io.github.jpersist.tools.jakarta} and {@code io.github.jpersist.tools.legacy}) export no packages; interaction occurs exclusively through the SPI interfaces in the API module.
  • Deep reflection boundaries — modularized applications that use {@code HibernateEnhancer} for build-time bytecode enhancement must open their entity packages to the relevant provider module (e.g. {@code opens com.example.domain to io.github.jpersist.tools.jakarta}) to allow Hibernate's reflective metadata access.

Version 3.0.0

Version 3.0.0 relocates all published artifacts to the {@code io.github.jpersist.tools} group and introduces the following changes:

  • Group relocation — all Maven coordinates now use the {@code io.github.jpersist.tools} group identifier.
  • {@link persistence.tools.spi.PersistenceServiceProvider} — new root service-provider interface shared by both the linting and enhancement hierarchies, with version-to-namespace mapping and generic {@link java.util.ServiceLoader} discovery via {@link persistence.tools.spi.PersistenceServiceProvider#getServiceProvider(String, Class)}.
  • {@link persistence.tools.Enhancer} and {@link persistence.tools.spi.EnhancerProvider} — new SPI for build-time Hibernate bytecode enhancement of entity classes, with configurable options for lazy initialisation, dirty tracking, association management, and extended enhancement.

Version 2.1.0

Version 2.1.0 introduced the unified linter hierarchy:

  • {@link persistence.tools.PersistenceLinter} — marker interface that serves as the root type for all linting operations.
  • {@link persistence.tools.spi.PersistenceLinterFactory} — base factory with generic discovery via {@link persistence.tools.spi.PersistenceLinterFactory#newPersistenceLinterFactory(String, Class)}.
  • {@link persistence.tools.SchemaValidator} and {@link persistence.tools.spi.SchemaValidatorFactory} — SPI for build-time database schema validation against the entity metamodel.

Version 2.0.0

Version 2.0.0 introduced the {@link persistence.tools.NamedObjectParser} and {@link persistence.tools.spi.NamedObjectParserFactory} APIs with support for validating {@link persistence.tools.NamedObjectType#STORED_PROCEDURE named stored procedures} alongside named queries, returning rich {@link persistence.tools.NamedObjectDescriptor} results containing parameter metadata.

Modules

persistence-tools-api
Defines the Service Provider Interfaces (SPIs): {@link persistence.tools.spi.PersistenceServiceProvider}, {@link persistence.tools.PersistenceLinter}, {@link persistence.tools.spi.PersistenceLinterFactory}, {@link persistence.tools.NamedObjectParser}, {@link persistence.tools.spi.NamedObjectParserFactory}, {@link persistence.tools.SchemaValidator}, {@link persistence.tools.spi.SchemaValidatorFactory}, {@link persistence.tools.Enhancer}, and {@link persistence.tools.spi.EnhancerProvider}. This module contains no implementation; provider modules are discovered at runtime through the {@link java.util.ServiceLoader} mechanism. It also hosts the shared model types {@link persistence.tools.NamedObjectDescriptor} and {@link persistence.tools.NamedObjectType}, as well as the enhancement option enum {@link persistence.tools.Enhancer.Option}.
persistence-tools-jakarta
Jakarta Persistence (JPA 3.x) provider. Uses Hibernate ORM 6 to compile JPQL queries into Semantic Query Model (SQM) trees, validate database schemas, and enhance entity bytecode.
Key classes: {@code hibernate.persistence.tools.provider.HibernateNamedObjectParserFactory}, {@code hibernate.persistence.tools.HibernateNamedObjectParser}, {@code hibernate.persistence.tools.provider.HibernateSchemaValidatorFactory}, {@code hibernate.persistence.tools.HibernateSchemaValidator}, {@code hibernate.persistence.tools.provider.HibernateEnhancerProvider}, and {@code hibernate.persistence.tools.HibernateEnhancer}.
persistence-tools-legacy
Legacy {@code javax.persistence} (JPA 2.x) provider. Uses Hibernate 5 and its AST-based query translator to validate JPQL queries and database schemas, and to enhance entity bytecode.
Key classes: {@code hibernate.persistence.tools.provider.HibernateNamedObjectParserFactory}, {@code hibernate.persistence.tools.HibernateNamedObjectParser}, {@code hibernate.persistence.tools.provider.HibernateSchemaValidatorFactory}, {@code hibernate.persistence.tools.HibernateSchemaValidator}, {@code hibernate.persistence.tools.provider.HibernateEnhancerProvider}, and {@code hibernate.persistence.tools.HibernateEnhancer}.
persistence-tools-bom
Bill of Materials (BOM) for convenient dependency management of all Persistence Tools modules.

Getting Started

Enhancing Entity Bytecode

Use {@link persistence.tools.spi.EnhancerProvider#getHibernateEnhancerProvider(String)} to obtain the appropriate provider for a given JPA specification version, then create a {@link persistence.tools.Enhancer} to transform entity classes at build time: 

{@code
    HibernateEnhancerProvider provider =
        HibernateEnhancerProvider.getHibernateEnhancerProvider("3.1");

    HibernateEnhancer enhancer = provider.getEnhancer(
        classesDir,
        classpathFiles,
        Map.of(
            HibernateEnhancer.Option.LAZY_INITIALIZATION, true,
            HibernateEnhancer.Option.DIRTY_TRACKING, true));

    byte[] enhancedBytes = enhancer.enhance(
        "com.example.Order", originalClassBytes);
}

Validating Named Queries and Stored Procedures

Use {@link persistence.tools.spi.NamedObjectParserFactory#newNamedObjectParserFactory(String)} to obtain the appropriate factory for a given JPA specification version, then create a {@link persistence.tools.NamedObjectParser} to validate named queries and stored procedures: 

{@code
    NamedObjectParserFactory factory =
        NamedObjectParserFactory.newNamedObjectParserFactory("3.1");

    try (NamedObjectParser parser = factory.newNamedObjectParser(entityClassNames)) {

        // Validate a named query
        NamedObjectDescriptor queryDescriptor = parser.parseQuery(
            "Order.findByStatus",
            "SELECT o FROM Order o WHERE o.status = :status");

        // Validate a named stored procedure
        NamedObjectDescriptor procDescriptor = parser.parseStoredProcedure(
            "Order.archiveOldOrders",
            "sp_archive_orders",
            Set.of("cutoffDate", "archiveTable"));
    }
}

Validating Database Schemas

Use {@link persistence.tools.spi.SchemaValidatorFactory#newSchemaValidatorFactory(String)} to obtain a schema validator factory, then create a {@link persistence.tools.SchemaValidator} and validate the entity metamodel against a live database: 

{@code
    SchemaValidatorFactory factory =
        SchemaValidatorFactory.newSchemaValidatorFactory("3.1");
    SchemaValidator validator = factory.newSchemaValidator(entityClassNames);

    validator.validateSchema(Map.of(
        "driver",   "org.h2.Driver",
        "url",      "jdbc:h2:mem:testdb",
        "username", "sa",
        "password", ""));
}

Generic Factory Discovery

The {@link persistence.tools.spi.PersistenceLinterFactory#newPersistenceLinterFactory(String, Class)} method provides a generic way to discover any linter factory subtype for a given JPA version: 

{@code
    // Equivalent to NamedObjectParserFactory.newNamedObjectParserFactory("3.1")
    NamedObjectParserFactory parserFactory =
        PersistenceLinterFactory.newPersistenceLinterFactory(
            "3.1", NamedObjectParserFactory.class);

    // Equivalent to SchemaValidatorFactory.newSchemaValidatorFactory("3.1")
    SchemaValidatorFactory schemaFactory =
        PersistenceLinterFactory.newPersistenceLinterFactory(
            "3.1", SchemaValidatorFactory.class);
}
