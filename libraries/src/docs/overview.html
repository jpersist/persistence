Lint Persistence Libraries

The Lint Persistence Libraries provide build-time validation of JPA persistence artifacts — named JPQL queries, stored procedure declarations, and database schemas — without deploying the application. By compiling query strings against the entity metamodel and comparing the metamodel with a live database schema at build time, syntax errors, unknown entity references, invalid property paths, and schema mismatches are caught early.

Architecture

The library is organised around a two-level SPI hierarchy rooted in {@link persist.lint.api.spi.PersistenceLinter} (the marker interface for all linting operations) and {@link persist.lint.api.spi.PersistenceLinterFactory} (the base factory with {@link java.util.ServiceLoader}-based discovery):

  • {@link persist.lint.api.spi.NamedObjectParser} / {@link persist.lint.api.spi.NamedObjectParserFactory} — parses and validates named JPQL queries and stored procedure declarations, returning {@link persist.lint.api.NamedObjectDescriptor} results with parameter metadata.
  • {@link persist.lint.api.spi.SchemaValidator} / {@link persist.lint.api.spi.SchemaValidatorFactory} — validates the entity metamodel against a live database schema via JDBC.

Provider implementations for each JPA namespace are shipped in separate modules and are resolved at runtime by passing a JPA specification version (e.g. {@code "3.1"} or {@code "2.2"}) to the appropriate factory method. The version is mapped internally to a persistence namespace ({@code "jakarta"} for JPA 3.x, {@code "javax"} for JPA 2.x).

What's New

Version 2.1.0

Version 2.1.0 introduces the unified linter hierarchy:

  • {@link persist.lint.api.spi.PersistenceLinter} — marker interface that serves as the root type for all linting operations.
  • {@link persist.lint.api.spi.PersistenceLinterFactory} — base factory with generic discovery via {@link persist.lint.api.spi.PersistenceLinterFactory#newPersistenceLinterFactory(String, Class)}.
  • {@link persist.lint.api.spi.SchemaValidator} and {@link persist.lint.api.spi.SchemaValidatorFactory} — new SPI for build-time database schema validation against the entity metamodel.

Version 2.0.0

Version 2.0.0 introduces the {@link persist.lint.api.spi.NamedObjectParser} and {@link persist.lint.api.spi.NamedObjectParserFactory} APIs, which replace the previous {@link persist.lint.query.spi.QueryParser} and {@link persist.lint.query.spi.QueryParserFactory} (now deprecated). The new API adds support for validating {@link persist.lint.api.NamedObjectType#STORED_PROCEDURE named stored procedures} alongside named queries, and returns rich {@link persist.lint.api.NamedObjectDescriptor} results containing parameter metadata.

Modules

lint-persistence-api
Defines the Service Provider Interface (SPI): {@link persist.lint.api.spi.PersistenceLinter}, {@link persist.lint.api.spi.PersistenceLinterFactory}, {@link persist.lint.api.spi.NamedObjectParser}, {@link persist.lint.api.spi.NamedObjectParserFactory}, {@link persist.lint.api.spi.SchemaValidator}, and {@link persist.lint.api.spi.SchemaValidatorFactory}. This module contains no implementation; provider modules are discovered at runtime through the {@link java.util.ServiceLoader} mechanism. It also hosts the shared model types {@link persist.lint.api.NamedObjectDescriptor} and {@link persist.lint.api.NamedObjectType}.

The legacy {@link persist.lint.query.spi} package ({@link persist.lint.query.spi.QueryParser} and {@link persist.lint.query.spi.QueryParserFactory}) is deprecated in favour of the {@link persist.lint.api.spi} package.
lint-persistence-jakarta
Jakarta Persistence (JPA 3.x) provider. Uses Hibernate ORM 6 to compile JPQL queries into Semantic Query Model (SQM) trees and to validate database schemas.
Key classes: {@link persist.lint.jakarta.JakartaNamedObjectParserFactory}, {@link persist.lint.jakarta.JakartaNamedObjectParser}, {@link persist.lint.jakarta.JakartaSchemaValidatorFactory}, and {@link persist.lint.jakarta.JakartaSchemaValidator}.
lint-persistence-legacy
Legacy {@code javax.persistence} (JPA 2.x) provider. Uses Hibernate 5 and its AST-based query translator to validate JPQL queries and database schemas.
Key classes: {@link persist.lint.legacy.LegacyNamedObjectParserFactory}, {@link persist.lint.legacy.LegacyNamedObjectParser}, {@link persist.lint.legacy.LegacySchemaValidatorFactory}, and {@link persist.lint.legacy.LegacySchemaValidator}.
lint-persistence-bom
Bill of Materials (BOM) for convenient dependency management of all Lint Persistence modules.

Getting Started

Validating Named Queries and Stored Procedures

Use {@link persist.lint.api.spi.NamedObjectParserFactory#newNamedObjectParserFactory(String)} to obtain the appropriate factory for a given JPA specification version, then create a {@link persist.lint.api.spi.NamedObjectParser} to validate named queries and stored procedures: 

{@code
    NamedObjectParserFactory factory = NamedObjectParserFactory.newNamedObjectParserFactory("3.1");

    try (NamedObjectParser parser = factory.newNamedObjectParser(entityClassNames)) {

        // Validate a named query
        NamedObjectDescriptor queryDescriptor = parser.parseQuery(
            "Order.findByStatus",
            "SELECT o FROM Order o WHERE o.status = :status");

        // Validate a named stored procedure
        NamedObjectDescriptor procDescriptor = parser.parseStoredProcedure(
            "Order.archiveOldOrders",
            "sp_archive_orders",
            Set.of("cutoffDate", "archiveTable"));
    }
}

Validating Database Schemas

Use {@link persist.lint.api.spi.SchemaValidatorFactory#newSchemaValidatorFactory(String)} to obtain a schema validator factory, then create a {@link persist.lint.api.spi.SchemaValidator} and validate the entity metamodel against a live database: 

{@code
    SchemaValidatorFactory factory = SchemaValidatorFactory.newSchemaValidatorFactory("3.1");
    SchemaValidator validator = factory.newSchemaValidator(entityClassNames);

    validator.validateSchema(Map.of(
        "driver",   "org.h2.Driver",
        "url",      "jdbc:h2:mem:testdb",
        "username", "sa",
        "password", ""));
}

Generic Factory Discovery

The {@link persist.lint.api.spi.PersistenceLinterFactory#newPersistenceLinterFactory(String, Class)} method provides a generic way to discover any linter factory subtype for a given JPA version: 

{@code
    // Equivalent to NamedObjectParserFactory.newNamedObjectParserFactory("3.1")
    NamedObjectParserFactory parserFactory =
        PersistenceLinterFactory.newPersistenceLinterFactory("3.1", NamedObjectParserFactory.class);

    // Equivalent to SchemaValidatorFactory.newSchemaValidatorFactory("3.1")
    SchemaValidatorFactory schemaFactory =
        PersistenceLinterFactory.newPersistenceLinterFactory("3.1", SchemaValidatorFactory.class);
}
