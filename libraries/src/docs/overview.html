Lint Persistence Libraries

The Lint Persistence Libraries provide build-time validation of named JPQL queries defined in JPA projects. By compiling query strings against the entity metamodel at build time, syntax errors, unknown entity references, and invalid property paths are caught early — before the application is deployed.

Modules

lint-persistence-api
Defines the Service Provider Interface (SPI): {@link persist.lint.query.spi.QueryParser} and {@link persist.lint.query.spi.QueryParserFactory}. This module contains no implementation; provider modules are discovered at runtime through the {@link java.util.ServiceLoader} mechanism.
lint-persistence-jakarta
Jakarta Persistence (JPA 3.x) provider. Uses Hibernate ORM 6 to compile JPQL queries into Semantic Query Model (SQM) trees. See {@link persist.lint.query.jakarta.JakartaQueryParserFactory}.
lint-persistence-legacy
Legacy {@code javax.persistence} (JPA 2.x) provider. Uses Hibernate 5 and its AST-based query translator to validate JPQL queries. See {@link persist.lint.query.legacy.LegacyQueryParserFactory}.
lint-persistence-bom
Bill of Materials (BOM) for convenient dependency management of all Lint Persistence modules.

Getting Started

Use {@link persist.lint.query.spi.QueryParserFactory#newQueryParserFactory(String)} to obtain the appropriate factory for a given JPA specification version, then create a {@link persist.lint.query.spi.QueryParser} to validate individual queries: 

{@code
    QueryParserFactory factory = QueryParserFactory.newQueryParserFactory("3.1");
    QueryParser parser = factory.newQueryParser(entityClassNames);
    parser.parseQuery("Order.findByStatus", "SELECT o FROM Order o WHERE o.status = :status");
}
