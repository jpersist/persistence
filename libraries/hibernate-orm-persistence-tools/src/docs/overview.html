Persistence Tools — Hibernate ORM 6 Provider

The Hibernate ORM Persistence Tools module ({@code io.github.jpersist.tools.hibernate.orm}) implements the persistence tooling SPIs for Jakarta Persistence (JPA 3.0, 3.1, and 3.2, {@code "jakarta"} namespace) using Hibernate ORM 6.

This module provides build-time bytecode enhancement, entity model linting, offline DDL schema export, Semantic Query Model (SQM) query and stored procedure validation, and JDBC database schema verification for modern Jakarta EE applications.

Key Capabilities & Implementations

1. Bytecode Enhancement

{@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateEnhancer} transforms compiled entity classes at build time using Hibernate ORM 6's enhancement engine. It instruments classes for:

  • Lazy-loading proxies and field interception
  • Inline dirty tracking to avoid expensive state snapshots
  • Bidirectional association management and synchronization
  • Extended enhancement optimizations

Enhancement settings can be configured using string property keys or the {@link hibernate.base.persistence.tools.HibernateEnhancerOption} enum.

2. Named Query & Stored Procedure Validation

{@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateNamedObjectParser} parses and validates named JPQL queries and stored procedure declarations by compiling query strings into Hibernate 6 Semantic Query Model (SQM) trees against the JPA entity metamodel.

3. Database Schema Validation

{@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateSchemaValidator} validates the entity metamodel against a target database schema via JDBC, ensuring tables, columns, data types, and foreign key constraints conform to JPA mappings.

4. Entity Model Linting

{@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateEntityModelLinter} inspects Jakarta Persistence entity classes for structural defects, mapping anti-patterns, and bad practices. It combines reflection-based class structure checks (e.g. non-final class/method rules, accessible no-arg constructors) with JPA association checks (detecting eager fetching on relationships, missing mappedBy attributes, and unordered @ManyToMany list collections).

5. Offline DDL Schema Export

{@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateSchemaExporter} generates offline database schema DDL scripts (CREATE, DROP, or BOTH) directly from Jakarta Persistence entity mappings targeting {@link java.io.File}, {@link java.io.OutputStream}, or {@link java.io.Writer} destinations without requiring an active database connection.

Configuration & Settings Reference

{@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateNamedObjectParser}, {@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateSchemaValidator}, and {@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.HibernateSchemaExporter} accept consumer-supplied configuration maps via their factory overloads (Map<String, Object>), merged using {@link hibernate.base.persistence.tools.HibernateUtil#mergeSettings}.

Named Object Parser Settings

Consumer settings override predefined defaults, while enforced invariants cannot be overwritten:

Named Object Parser Configuration Properties
Property Key Tier Value Purpose
hibernate.dialect Default org.hibernate.dialect.H2Dialect Baseline SQL dialect for offline SQM function resolution (overridable).
hibernate.boot.allow_jdbc_metadata_access Default "false" Explicitly disables background JDBC metadata connection passes.
jakarta.persistence.database-product-version Default "2.2.224" Prevents Hibernate 6 from falling back to minimum H2 dialect capabilities offline.
hibernate.connection.provider_class Default ...internal.NoOpConnectionProvider Suppresses HHH000181 startup logs when no data source is configured.
hibernate.jpa.compliance.query Default "true" Enforces strict Jakarta Persistence query compliance rules by default.
hibernate.bytecode.provider Default "none" Disables runtime bytecode enhancement routines during offline linting.
hibernate.hbm2ddl.auto Enforced "none" Guarantees schema DDL mutations remain disabled during query linting.

  • {@link persistence.tools.spi.PersistenceServiceProvider} — base implementation {@link io.github.jpersist.tools.hibernate.orm/hibernate.jakarta.persistence.tools.provider.HibernatePersistenceServiceProvider}

JPMS Strong Encapsulation

This module enforces strict encapsulation: all implementation packages are hidden and not exported. Consumers interact with this provider exclusively through the API contracts and SPIs provided by {@code io.github.jpersist.tools.api}.

When performing build-time bytecode enhancement on modularized entity projects, entity packages must be opened to this module to permit reflective inspection: 

{@code
module com.example.domain {
    requires jakarta.persistence;
    opens com.example.domain.model to io.github.jpersist.tools.hibernate.orm;
}
}
