Persistence Tools Core API & SPI

The Persistence Tools API module ({@code io.github.jpersist.tools.api}) provides vendor-agnostic abstractions and Service Provider Interfaces (SPI) for build-time validation, entity model linting, query parsing, schema verification, offline DDL export, and bytecode enhancement of JPA persistence artifacts.

By decoupling application tooling and build plugins from specific JPA provider implementations, this module enables consistent build-time analysis and schema management across different persistence specifications (e.g. Jakarta Persistence JPA 3.x and legacy Java Persistence JPA 2.x).

Architecture & Key Contracts

The API is divided into two primary package layers:

1. Public API Contracts (persistence.tools)

Defines the consumer-facing interfaces and data models for persistence tooling:

  • {@link persistence.tools.Enhancer} — Transforms compiled entity class bytecode at build time to incorporate runtime optimizations such as lazy-loading proxies, inline dirty tracking, and bidirectional association management.
  • {@link persistence.tools.EntityModelLinter} — Statically inspects the JPA entity metamodel at build time to detect mapping anti-patterns, structural errors, and performance pitfalls.
  • {@link persistence.tools.LintDiagnostic} — Immutable diagnostic record encapsulating a single linting finding (severity, rule ID, class name, attribute name, and descriptive message).
  • {@link persistence.tools.LintSeverity} — Enumeration classifying diagnostic severity levels ({@link persistence.tools.LintSeverity#ERROR ERROR}, {@link persistence.tools.LintSeverity#WARNING WARNING}, or {@link persistence.tools.LintSeverity#INFO INFO}).
  • {@link persistence.tools.NamedObjectParser} — Validates named JPQL queries and stored procedure declarations against the entity metamodel, returning rich metadata descriptors.
  • {@link persistence.tools.NamedObjectDescriptor} — Immutable descriptor encapsulating the validation results, target type, query/procedure name, and extracted parameter definitions.
  • {@link persistence.tools.NamedObjectType} — Enumeration classifying named persistence objects ({@link persistence.tools.NamedObjectType#QUERY QUERY} or {@link persistence.tools.NamedObjectType#STORED_PROCEDURE STORED_PROCEDURE}).
  • {@link persistence.tools.SchemaExporter} — Exports offline DDL scripts ({@link persistence.tools.SchemaExporter.Action#CREATE CREATE}, {@link persistence.tools.SchemaExporter.Action#DROP DROP}, or {@link persistence.tools.SchemaExporter.Action#BOTH BOTH}) from entity metadata without requiring a live database connection.
  • {@link persistence.tools.SchemaExporter.Action} — Enumeration defining the DDL generation scope.
  • {@link persistence.tools.SchemaValidator} — Validates the entity metamodel against a live database schema via JDBC connections.
  • {@link persistence.tools.PersistenceLinter} — Common marker interface for all persistence linting components.

2. Service Provider Interfaces (persistence.tools.spi)

Defines the factory interfaces and runtime discovery mechanisms implemented by provider modules:

  • {@link persistence.tools.spi.PersistenceServiceProvider} — Common root SPI for version-to-namespace mapping and {@link java.util.ServiceLoader}-based factory resolution.
  • {@link persistence.tools.spi.EnhancerProvider} — Factory SPI for discovering and instantiating namespace-specific bytecode enhancers with default or customized enhancement settings.
  • {@link persistence.tools.spi.EntityModelLinterFactory} — Factory SPI for discovering and instantiating entity model linters with default or customized configuration settings.
  • {@link persistence.tools.spi.NamedObjectParserFactory} — Factory SPI for creating named object query and procedure parsers with default or custom configuration settings.
  • {@link persistence.tools.spi.SchemaValidatorFactory} — Factory SPI for creating database schema validators with default or custom configuration settings.
  • {@link persistence.tools.spi.SchemaExporterFactory} — Factory SPI for creating offline DDL schema exporters with default or custom dialect and formatting settings.
  • {@link persistence.tools.spi.PersistenceLinterFactory} — Generic base factory SPI for discovering linter factory subtypes.

Service Discovery and Usage

Custom Configuration Settings

Persistence service provider factories ({@link persistence.tools.spi.EnhancerProvider}, {@link persistence.tools.spi.EntityModelLinterFactory}, {@link persistence.tools.spi.NamedObjectParserFactory}, {@link persistence.tools.spi.SchemaValidatorFactory}, and {@link persistence.tools.spi.SchemaExporterFactory}) overload their factory methods with custom settings parameters. This feature enables consumers to override default service implementation settings when instantiating tools, while also supporting convenient overloads that use default settings when custom configuration is omitted:

  • {@link persistence.tools.spi.EnhancerProvider#getEnhancer(java.util.Collection, java.util.Map)} and {@link persistence.tools.spi.EnhancerProvider#getEnhancer(java.util.Collection)}
  • {@link persistence.tools.spi.EntityModelLinterFactory#newEntityModelLinter(java.util.List, java.util.Map)} and {@link persistence.tools.spi.EntityModelLinterFactory#newEntityModelLinter(java.util.List)}
  • {@link persistence.tools.spi.NamedObjectParserFactory#newNamedObjectParser(java.util.List, java.util.Map)} and {@link persistence.tools.spi.NamedObjectParserFactory#newNamedObjectParser(java.util.List)}
  • {@link persistence.tools.spi.SchemaValidatorFactory#newSchemaValidator(java.util.List, java.util.Map)} and {@link persistence.tools.spi.SchemaValidatorFactory#newSchemaValidator(java.util.List)}
  • {@link persistence.tools.spi.SchemaExporterFactory#newSchemaExporter(java.util.List, java.util.Map)} and {@link persistence.tools.spi.SchemaExporterFactory#newSchemaExporter(java.util.List)}

Bytecode Enhancement

Obtain an enhancer for a specific JPA specification version (e.g. {@code "3.1"}) via {@link persistence.tools.spi.EnhancerProvider#getEnhancerProvider(String)}: 

{@code
EnhancerProvider provider = EnhancerProvider.getEnhancerProvider("3.1");
Enhancer enhancer = provider.getEnhancer(
    classpathFiles,
    Map.of("enhancement.option.lazy-initialization", true,
           "enhancement.option.dirty-tracking", true));

byte[] enhancedBytes = enhancer.enhance("com.example.Order", originalBytecode);
}

Entity Model Linting

Obtain an entity model linter factory via {@link persistence.tools.spi.EntityModelLinterFactory#newEntityModelLinterFactory(String)}. Linters statically inspect compiled entity classes and report diagnostics across mapping and performance rules: 

{@code
EntityModelLinterFactory factory = EntityModelLinterFactory.newEntityModelLinterFactory("3.1");
EntityModelLinter linter = factory.newEntityModelLinter(entityClassNames, Map.of("linter.strict", "true"));
List findings = linter.lint();

for (LintDiagnostic diagnostic : findings) {
    if (diagnostic.severity() == LintSeverity.ERROR) {
        System.err.println(diagnostic.ruleId() + " [" + diagnostic.className() + "]: " + diagnostic.message());
    }
}
}

Named Query and Stored Procedure Validation

Obtain a parser factory via {@link persistence.tools.spi.NamedObjectParserFactory#newNamedObjectParserFactory(String)}. Parsers can be created with default settings or with custom configuration settings: 

{@code
NamedObjectParserFactory factory = NamedObjectParserFactory.newNamedObjectParserFactory("3.1");
try (NamedObjectParser parser = factory.newNamedObjectParser(entityClassNames, settings)) {
    NamedObjectDescriptor queryDesc = parser.parseQuery(
        "Order.findByStatus", "SELECT o FROM Order o WHERE o.status = :status");

    NamedObjectDescriptor procDesc = parser.parseStoredProcedure(
        "Order.archive", "sp_archive_orders", Set.of("cutoffDate"));
}
}

Database Schema Validation

Obtain a schema validator factory via {@link persistence.tools.spi.SchemaValidatorFactory#newSchemaValidatorFactory(String)}. Validators can be created with default settings or configured with a settings map: 

{@code
SchemaValidatorFactory factory = SchemaValidatorFactory.newSchemaValidatorFactory("3.1");
SchemaValidator validator = factory.newSchemaValidator(entityClassNames, settings);
validator.validateSchema(Map.of(
    "driver",   "org.h2.Driver",
    "url",      "jdbc:h2:mem:testdb",
    "username", "sa",
    "password", ""));
}

Offline DDL Schema Export

Obtain a schema exporter factory via {@link persistence.tools.spi.SchemaExporterFactory#newSchemaExporterFactory(String)}. Exporters generate DDL statements without a live database connection and write the resulting scripts to a {@link java.io.File}, {@link java.io.OutputStream}, or {@link java.io.Writer}: 

{@code
SchemaExporterFactory factory = SchemaExporterFactory.newSchemaExporterFactory("3.1");
SchemaExporter exporter = factory.newSchemaExporter(
    entityClassNames,
    Map.of("hibernate.dialect", "org.hibernate.dialect.PostgreSQLDialect",
           "hibernate.format_sql", "true")
);

// Export CREATE DDL statements to a destination file
exporter.export(SchemaExporter.Action.CREATE, new File("build/schema/create.sql"));
}
